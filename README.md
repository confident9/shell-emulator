# Эмулятор командной оболочки UNIX (Вариант 30)

Проект представляет собой эмулятор командной оболочки UNIX-подобной операционной системы. Разработан в рамках учебного курса по дисциплине «Конфигурационное управление».

Эмулятор реализован на языке Python с графическим интерфейсом на базе библиотеки `tkinter` и поддерживает виртуальную файловую систему (VFS), работающую в оперативной памяти на основе JSON-файлов.

---

## Реализация по этапам задания

### Этап 1. REPL
Создан базовый рабочий прототип приложения.
- Графический интерфейс (GUI) на базе `tkinter`.
- Заголовок окна динамически формируется из системных данных ОС: `Эмулятор - [username@hostname]`.
- Парсер командной строки корректно обрабатывает аргументы в одинарных и двойных кавычках с помощью модуля `shlex`.
- Реализованы команды-заглушки `ls`, `cd`, выводящие имя команды и переданные аргументы, а также команда `exit`.
- Реализована обработка ошибок (неизвестные команды, незакрытые кавычки).

### Этап 2. Конфигурация
Добавлена поддержка параметров командной строки и стартовых скриптов.
- Поддерживаются параметры:
  - `--vfs` — путь к физическому расположению JSON-файла VFS;
  - `--script` — путь к стартовому скрипту для автоматического выполнения команд.
- При запуске приложения формируется отладочный вывод всех переданных параметров.
- Стартовые скрипты поддерживают комментарии (строки, начинающиеся с `#`).
- При исполнении скрипта на экране отображается как ввод, так и вывод команд, имитируя диалог с пользователем.
- Для тестирования параметров командной строки подготовлен скрипт ОС `scripts/run_test_config.sh`.

### Этап 3. VFS (Виртуальная файловая система)
Подключена модель файловой системы, функционирующая в памяти.
- Источником VFS является JSON-файл. Двоичные данные файлов кодируются в формат `base64`.
- Все операции производятся исключительно в памяти, без распаковки на физический диск.
- Реализована команда `vfs-save <путь>` для сохранения текущего состояния VFS обратно в JSON на диск.
- При старте эмулятора выводится сообщение из файла `motd` (если он присутствует в корне VFS).
- Подготовлены образцы VFS в папке `vfs_samples/`:
  - `minimal.json` — минимальный вариант (корень, motd, один файл);
  - `several_files.json` — несколько файлов и папок;
  - `full.json` — структура не менее 3 уровней вложенности (`/` -> `home` -> `user` -> `documents` -> `report.txt`).
- Для каждого варианта написаны проверочные скрипты ОС (`run_test_minimal.sh`, `run_test_several.sh`, `run_test_full.sh`).

### Этап 4. Основные команды
Реализована полноценная логика стандартных команд UNIX.
- `ls` — вывод содержимого текущей директории, указанного пути или информации о файле, с сортировкой по алфавиту.
- `cd` — смена текущего каталога. Поддерживаются абсолютные пути, относительные пути, `.` (текущий каталог), `..` (переход на уровень выше), переход в корень. Строка приглашения (prompt) обновляется при смене директории.
- `date` — вывод текущей даты и времени.
- `cal` — вывод календаря текущего месяца, указанного года (`cal 2026`) или месяца и года (`cal 10 2026`).
- Созданы стартовый скрипт `scripts/test_commands.sh` и скрипт ОС `scripts/run_test_commands.sh`.

### Этап 5. Дополнительные команды
Реализованы команды изменения состояния виртуальной файловой системы в памяти.
- `chmod <права> <путь>` — изменение прав доступа к файлу или каталогу в оперативной памяти.
- `touch <путь>` — создание пустого файла в указанной директории или обновление времени модификации существующего файла в памяти.
- Созданы стартовый скрипт `scripts/test_extra.sh` и скрипт ОС `scripts/run_test_extra.sh`.

## Поддерживаемые команды

| Команда | Синтаксис | Пример | Описание |
|---|---|---|---|
| `ls` | `ls [путь]` | `ls home/user` | Просмотр содержимого директории или файла |
| `cd` | `cd [путь]` | `cd ../documents` | Смена текущей рабочей директории |
| `date` | `date` | `date` | Вывод текущей даты и времени |
| `cal` | `cal [год] [месяц год]` | `cal 10 2026` | Вывод календаря месяца или года |
| `chmod` | `chmod <права> <путь>` | `chmod 755 motd` | Изменение прав доступа узла в памяти |
| `touch` | `touch <путь>` | `touch file.txt` | Создание файла / обновление времени |
| `vfs-save` | `vfs-save <путь>` | `vfs-save backup.json` | Сохранение текущего состояния VFS на диск |
| `exit` | `exit` | `exit` | Завершение работы эмулятора |

## Сборка и запуск

Для работы требуется Python 3.8+ со стандартной библиотекой (`tkinter`, `shlex`, `json`, `base64`, `unittest`).

### Основные сценарии запуска

Запуск в графическом режиме GUI (по умолчанию):
```bash
python3 main.py --vfs vfs_samples/full.json
```

Запуск со стартовым скриптом:
```bash
python3 main.py --vfs vfs_samples/full.json --script scripts/test_commands.sh
```

Запуск в консольном режиме (терминальный REPL):
```bash
python3 main.py --cli --vfs vfs_samples/full.json
```

Либо через исполняемый скрипт:
```bash
chmod +x run.sh
./run.sh --vfs vfs_samples/full.json
```

## Тестирование

### Модульные тесты
В проекте реализовано 50 модульных тестов на базе библиотеки `unittest`.  
Тесты проверяют корректность синтаксического анализа кавычек, обработку путей и узлов VFS, логику всех команд, обработку ошибок и циклы исполнения скриптов.

Запуск тестов:
```bash
python3 -m unittest discover tests -v
# или
./run.sh test
```

### Сценарии тестирования ОС
Запуск всех проверочных сценариев операционной системы:
```bash
./run.sh all
```
