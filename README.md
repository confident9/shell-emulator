# Эмулятор командной оболочки ОС UNIX (Вариант №30)

Учебный проект по разработке эмулятора командной строки UNIX-подобной операционной системы с графическим интерфейсом (GUI) и виртуальной файловой системой (VFS).

---

## ⚡ Быстрый старт: Решение проблемы с открытием эмулятора

Если у вас не открывается эмулятор или возникает ошибка `command not found: python`:

### Основные причины и решения:

1. **Команда `python` не найдена на macOS**:
   На современных версиях macOS (macOS Monterey 12.3 и новее) предустановлен только `python3`. Команды `python` по умолчанию нет.
   👉 **Используйте команду `python3`**:
   ```bash
   python3 main.py
   ```

2. **Запуск двойным кликом на macOS (Finder)**:
   Файлы `.py` и `.sh` в macOS открываются в текстовом редакторе. Для запуска кликом используйте специальный лаунчер:
   👉 **Дважды кликните по файлу `run.command`** в Finder! Он автоматически откроет терминал и запустит эмулятор.

3. **Проблемы с библиотекой Tkinter на Mac**:
   Если окно Tkinter не отображается, зависает или отсутствует библиотека `_tkinter`:
   👉 **Запустите встроенный Web GUI (в браузере)**:
   ```bash
   python3 main.py --web
   # или
   ./run.sh --web
   ```
   *Web GUI не требует никаких сторонних библиотек, работает на стандартных модулях Python и открывает графический терминал прямо в вашем браузере (Safari, Chrome и др.).*

4. **Запуск напрямую в терминале (консольный режим)**:
   ```bash
   python3 main.py --cli
   # или
   ./run.sh --cli
   ```

## 🚀 Режимы работы эмулятора

| Режим | Команда запуска | Описание |
|---|---|---|
| **Десктопный GUI** | `python3 main.py` | Окно Tkinter (при сбое автоматически переключится на Web GUI) |
| **Web GUI (браузер)** | `python3 main.py --web` | Графический терминал в браузере (Safari/Chrome) |
| **CLI (терминал)** | `python3 main.py --cli` | Интерактивный терминальный REPL |
| **Двойной клик на Mac**| Запуск `run.command` | Открывает эмулятор через macOS Terminal |

### Дополнительные параметры командной строки:
- `--vfs <путь>` — путь к физическому JSON-файлу виртуальной файловой системы (VFS).
- `--script <путь>` — путь к стартовому скрипту эмулятора.
- `--mode <gui|web|cli>` — выбор режима интерфейса.

Примеры:
```bash
# Запуск с полной VFS (не менее 3 уровней вложенности)
python3 main.py --vfs vfs_samples/full.json

# Запуск с VFS и выполнением стартового скрипта
python3 main.py --vfs vfs_samples/full.json --script scripts/test_commands.sh

# Запуск в Web GUI с VFS
python3 main.py --web --vfs vfs_samples/full.json
```

## 📋 Описание этапов выполнения задания (Вариант №30)

### Этап 1. REPL
- Реализован графический интерфейс (GUI).
- Заголовок окна формируется на основе данных ОС: `Эмулятор - [username@hostname]`.
- Парсер аргументов (`src/parser.py`) корректно обрабатывает кавычки (одинарные, двойные, экранирование) с помощью `shlex`.
- Команды-заглушки `ls`, `cd` и завершение работы `exit`.
- Обработка ошибок (неизвестные команды, незакрытые кавычки).

### Этап 2. Конфигурация
- Поддержка параметров командной строки `--vfs` и `--script`.
- Отладочный вывод всех параметров при старте приложения.
- Стартовые скрипты эмулятора с поддержкой комментариев (`#`).
- Отображение ввода и вывода при исполнении скрипта, имитируя диалог с пользователем.
- Скрипт ОС `scripts/run_test_config.sh` тестирует все комбинации параметров.

### Этап 3. VFS (Виртуальная файловая система)
- Все операции проводятся строго в оперативной памяти без распаковки на диск.
- Источник VFS — JSON-файлы с кодированием двоичных данных в `base64`.
- Команда `vfs-save <путь>` для сохранения текущего состояния VFS на диск в исходном формате JSON.
- Автоматический вывод сообщения из файла `motd` в корне VFS при старте.
- Образцы VFS в каталоге `vfs_samples/`:
  - `minimal.json` — минимальная VFS (корень, motd, 1 файл);
  - `several_files.json` — VFS с несколькими файлами и папками;
  - `full.json` — полная VFS с более чем 3 уровнями вложенности (`/` -> `home` -> `user` -> `documents` -> `report.txt`).
- Скрипты ОС: `run_test_minimal.sh`, `run_test_several.sh`, `run_test_full.sh`.

### Этап 4. Основные команды
- Полноценная логика для `ls` (просмотр каталогов, файлов, сортировка, обработка ошибок).
- Полноценная логика для `cd` (абсолютные и относительные пути, переход в `..`, `.`, корень, обновление prompt).
- Новые команды:
  - `date` — вывод текущей даты и времени;
  - `cal` — вывод календаря (текущий месяц, конкретный год, месяц и год).
- Стартовый скрипт `scripts/test_commands.sh` и скрипт ОС `scripts/run_test_commands.sh`.

### Этап 5. Дополнительные команды
- Команда `chmod <права> <путь>` — изменение прав доступа в памяти.
- Команда `touch <путь>` — создание пустого файла или обновление времени модификации в памяти.
- Стартовый скрипт `scripts/test_extra.sh` и скрипт ОС `scripts/run_test_extra.sh`.

## 🛠 Поддерживаемые команды эмулятора

| Команда | Синтаксис | Пример | Описание |
|---|---|---|---|
| `ls` | `ls [путь]` | `ls home/user` | Вывод содержимого каталога или имени файла |
| `cd` | `cd [путь]` | `cd ..` или `cd /home` | Смена текущего каталога |
| `date` | `date` | `date` | Текущая дата и время UNIX |
| `cal` | `cal [год] [месяц год]` | `cal 2026` или `cal 10 2026` | Календарь |
| `chmod` | `chmod <права> <путь>` | `chmod 755 motd` | Изменение прав доступа в VFS |
| `touch` | `touch <путь>` | `touch test.txt` | Создание файла / обновление времени |
| `vfs-save` | `vfs-save <путь.json>` | `vfs-save dump.json` | Экспорт VFS в JSON-файл |
| `exit` | `exit` | `exit` | Выход из эмулятора |

## 🧪 Запуск автоматических тестов

В проекте реализовано 50 модульных тестов (`unittest`), покрывающих парсер, VFS, команды и ядро эмулятора.

Запуск всех тестов:
```bash
./run.sh test
# или
python3 -m unittest discover -s tests -v
```

Запуск всех проверочных скриптов ОС:
```bash
./run.sh all
```
